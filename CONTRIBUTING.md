# Contributing / 贡献

1. Keep a change focused and describe the observed problem and resulting behavior.
2. Use anonymous fixtures. Do not add real account IDs, absolute personal paths, access tokens, audio references or model weights.
3. Add meaningful checks for authorization, queueing, termination or data boundaries when those behaviors change. Run the existing suite and public-source scanner.
4. State which optional engines/platforms were actually tested. Do not turn a successful API receipt into a claim of human-like behavior or completed delivery.
5. Update both READMEs when feature status, setup requirements or permissions change. Preserve asset provenance and third-party terms.

中文问题和PR均欢迎。请写清复现步骤、预期与实际结果，附匿名日志片段即可，不要上传个人实例文件。
