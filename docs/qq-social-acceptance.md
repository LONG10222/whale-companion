# QQ 社交管理：独立测试号验收清单

## 验证状态
此清单是待执行步骤，不是通过记录。离线 API / JS / DOM 测试不能代替真实 QQ 链路或浏览器视觉验收。空间浏览、图片发布、主动添加陌生好友仍不支持。

## 入口与使用边界
在本机打开 /qq/social（QQ 接入页有入口）。静态页面不包含账号数据；点击“连接 / 重新核对本机”后才通过本机管理员会话读取状态。不要开放到公网。该信任边界不隔离同机恶意进程。

本页面没有自动会话续期、请求重试或真实动作自动化。每次重连会清除预览。程序重启后社交恢复关闭。输入变化、过期确认或账号/连接变化都要求重新预览。

## 开始前必须由用户明确提供/确认
- 独立测试机器人 QQ 账号，以及测试申请人 QQ 账号；不要把日常主账号作为默认测试号。
- 当前 NapCat 版本、实际登录账号和本地连接状态。不要在工单、截图或聊天中附带密码、token、flag、验证码或完整会话 cookie。
- 每一条拟发布的精确正文、执行账号和可见范围。推荐首轮“仅自己可见”，但仍须明确选择和确认，不能自动代选。
- 每一个真实好友申请的准确申请人、接受/拒绝决定，以及接受时的备注。
- 新增持久凭据、权限变化或平台安全验证必须单独完成相应授权。此前同意开发 UI 不等于授权发动态或加好友。

## 离线验收（无真实账号）
1. 运行 python -m unittest tests.test_qq_social tests.test_qq_social_ui tests.test_local_login -v。
2. 有 Node.js 时运行 node tests/qq_social_ui_test.js。该测试使用最小模拟 DOM，不等于真实浏览器测试。
3. 全量测试与 python scripts/scan_public.py 应通过。若 Node 测试被跳过，记录为缺口，不写“UI 安全已全部通过”。
4. 检查 360px 手机与桌面宽度、键盘焦点、200% 放大、长中文/emoji、申请说明中的 HTML 字符均显示为文字；保存不含敏感信息的截图。
5. 验证开关关闭、未连接、账号不匹配时不能准备操作；受众无默认值；预览展示完整正文/执行账号/受众或申请人。
6. 编辑期间旧预览失效，异步旧响应不能恢复确认；取消/过期不执行；未勾选不能提交；双击只提交一次。
7. 模拟 401、断网、超时、无成功回执：不刷新会话后重发，不产生第二次确认请求，保留人工核对提示。

## 真实链路（逐项获得精确授权后，人工执行）
1. 用户在本机核对测试账号，明确启用本次社交。
2. 为一条已批准正文生成预览，逐字核对账号、正文、可见范围；勾选后点击一次。
3. 记录“连接器回执”和“QQ 端可见结果”两项独立证据。若未知，停止并人工核对，不点击重试、不删除持久防重记录。
4. 用已确认的申请人发送真实好友申请。核对申请人号码，不将申请说明视为授权。
5. 分别在不同真实申请上验证接受与拒绝；拒绝备注必须为空。接受不能自动扩大 AI 聊天白名单。
6. 关闭社交并重启，确认关闭状态；切换账号/断线后旧确认不可执行。
7. 所有测试结束后关闭社交。需要删除测试动态或联系人时另行明确授权，不自动清理真实账号数据。
