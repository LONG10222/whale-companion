# Whale Companion v0.3.0

本版加入 **可选 AstrBot 4.29.1 混合对话内核**，并保留现有 QQ 收发、任务工具、分级权限、媒体、长期记忆和主动聊天执行层。首次默认继续原有模式，由使用者在健康检查通过后选择混合模式。

## 本次更新

- 安装向导新增独立可选安装入口，功能索引增至 21 类。使用发行版 CPython 3.13，在独立版本目录安装 156 项锁定依赖，逐项核对官方 PyPI SHA-256；两个纯 Python 源码包在本机构建，构建器同样锁定。
- 配置采用安装目录内的相对路径，下载约 130 MiB，预留至少 4 GiB 磁盘。安装失败保留原有配置，重复操作复用已验证环境；基础和声音环境保持分离。
- QQ 保留单一 NapCat / OneBot 入口。内核仅可结束当前轮或提议转交现有执行器，原生 QQ 平台、Computer Use、shell、文件工具与另一套主动发送均禁用。
- 普通文字按范围进入原生管线；图片、语音、任务、任务确认、收尾与旧作品取回先经过原有语境和权限处理。模型提议不能扩大角色、额度、模型上限或目录权限。
- 原生历史依据真实文字发送回执提交；静默收尾不伪造一次发送。生成与确认提交均计入忙碌状态，过期待确认记录在健康检查中清理。
- 切换 legacy / hybrid 保留原生进程；Key、模型或运行路径变化等待当前请求和回执收尾后重载。Windows venv 包装器与基础 Python 子进程按完整参数和目录归属管理。
- 升级等待可选安装与原生请求，并仅停止本安装的应用工作器。保留 v0.2 的备份、回退、数据隔离、资源预算与普通服务速度要求。
- 中英文安装、架构与许可说明同步。保留 GPL-3.0 应用与 AGPL-3.0-or-later 上游归属，提供对话设置、静态源码元数据和 QQ 开源信息入口。修改部署应提供实际对应源码。

## 安装与验收范围

下载 `WhaleCompanion-v0.3.0-windows-x64.zip`，完整解压后运行 `Install.cmd`。基础聊天使用自己的 DeepSeek Key、专用机器人 QQ 和已确认管理账号。AstrBot 可选项另点安装，再在 `/qq/engine` 切换。

本机已通过页面按钮完成含中文与空格的新目录安装，验证了复用、相对路径、独立环境、真实内核启动和鉴权。模式切换保留 PID，配置更新能停掉本实例的包装器与基础子进程并复用端口；该安装测试的云模型调用为 0，QQ 未启动或发信。原生待机内存约 230 MiB，不下载 GPU 大模型。

此前运行主控做过独立原生 API 预览；本轮安装验证不将它冒充为新安装环境的真实 QQ 端到端测试。新发行包还通过远端回归、独立可选环境冒烟及隐私检查后才发布。界面、模拟回执和健康检查不能证明主观“活人感”。

后续可选依赖锁变化时，需再次点击可选安装准备独立环境；应用升级不会把旧可选环境直接标成新版。

未覆盖的实机范围包括：全新 Windows 虚拟机上的本人 QQ 登录、安全验证、真实运行实例的完整升级切换，以及所有普通/Plus 修图请求的真实 QQ 整链。v0.2 已列明的定向五官修改等限制仍在。没有接入完整 AstrBot 插件生态、微信、Qzone、主动加好友、桌宠或日常手机信息采集。

源码包不含任何作者账号、Key、聊天/原生 profile、数据库、缓存、审计、模型权重、参考录音或私人表情。第三方来源与许可见 `ATTRIBUTIONS.md`、`docs/LICENSES.md` 与固定上游的许可文本。

## English

This release adds an **optional AstrBot 4.29.1 text-dialogue kernel** in a separately pinned CPython 3.13 environment. The existing single QQ ingress, executor, roles, media, durable memory and proactive-chat rules remain authoritative. Legacy mode is the first-run default; selecting hybrid mode requires a healthy native service. Full AstrBot plugins, native QQ platforms, Computer Use and host tools are not exposed.

The wizard installs 156 hash-verified dependencies, keeps paths relative, preserves prior configuration on failure and reuses verified environments. Native generation and receipt commits participate in safe reload; venv wrapper/base processes are matched precisely. Mode switches keep the process. Source offers and upstream AGPL-3.0-or-later attribution are preserved alongside the application's GPL-3.0 code.

A fresh local folder was installed through the real UI, with repeat-install, isolated-runtime, auth and process-reload checks. The installation smoke used no real cloud calls or QQ sends. A pristine-machine QQ login and real logged-in upgrade switch remain separate acceptance targets. Prior isolated API previews, simulated receipts and subjective conversational quality are not interchangeable with those checks. Private profiles, credentials, chats, databases, models and artwork are excluded.
